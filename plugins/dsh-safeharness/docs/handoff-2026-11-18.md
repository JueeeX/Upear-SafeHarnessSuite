## 2. 坐标系：三个东西，别混

1. **Upear / SafeHarnessSuite 主项目**（仓库根，`src/safeharness/**`、`SUMC/**`）
   - Python。**其它 Agent 在推进，本会话明确不碰**。
   - 本文里简称“**内核**”。它的一部分代码（`policies/inform.py`、`sql_guard.py`、`trajectory.py`、`runtime/redaction.py`、`posture_check.py`、`deploy_patrol.py`、`rules_loader.py`；SUMC 侧 `core/llm/safeharness_mcp_guard.py`、`core/memory/sanitizer.py`）是插件**逐条对照移植**的来源。
2. **插件**（`plugins/dsh-safeharness`）
   - TypeScript，跑在 DSH 进程内，通过 Cordis 事件接缝拦截。
   - 有自己独立的规则集（`rules/inform.yaml`，20 条，与内核 `_DEFAULT_PATTERNS` 逐条同源）、账本、姿态/巡检、面板。
3. **两者的关系**：插件是应用层；内核是策略/服务端层。**插件不 import 内核，内核也不知道插件存在**。改插件不能“顺手”改内核；反过来也一样。

> 曾经的设计约束（用户明确要求，仍然有效）：**插件不凌驾于内核**——只移植内核里**已经实现**的能力；内核没有的（记忆/embedding、租户、PG sink、网关回执、管理面、进化闸门）一律不做；宿主已经托管的（审批对话框、OS 沙箱、工具执行）不重造。

面板：`插件 → @upear/dsh-safeharness`（五个标签：概览 / 事件 / 规则 / 巡检 / 设置）。设置里也有一份（`settings.plugins.tab`）。

模型侧（或 `/safeharness status`）：

```json
{
  "loaded": true, "version": "1.15.0", "preset": "balanced",
  "ruleCount": 20, "chainCount": 3, "rulesetHash": "…",
  "modes": { "input": "enforce", "tools": "enforce", "results": "enforce", "output": "warn", "approval": "delegate" },
  "seams": { "input": true, "tools": true, "guard": true, "llm": true, "approval": true, "prompt": true, "commands": true, "settings": true },
  "ledger": { "writable": true, "records": 6, "path": "…ledger.ndjson" },
  "judge": { "enabled": true, "scope": "flagged", "available": true, "provider": "liao", "model": "gpt-6-luna" },
  "engine": { "kind": "builtin", "status": "ready", "rulesStale": false }
}
```

判读规则：

- `seams.* = false`：该 profile 没提供那个宿主能力（例如 headless 没有 `commands`），不是插件坏了。
- `ledger.writable = false` + `audit.required = true`：执行面会被拒绝（故意的 fail-closed）。
- `engine.status = failed`：sidecar 配置了但起不来（本机未启用 sidecar，`kind: builtin`）。
- `version` 与 `package.json` 不一致 = profile 里装的是旧包（重装，见 §14）。

## 5. 架构与数据流（为什么这样分层）

```
DSH 进程
├─ 输入:  agent/pre-step ──► hooks/input.ts ──► engine/input.ts (+judge/input.ts, engine/normalize.ts)
├─ 工具:  tools/pre-execute (async) ──► hooks/tools.ts ──► engine/tool.ts (名字/标签/SQL/描述符/链/阈值)
│         ctx.tools.guard (sync, 单调兜底)  ─┘            （无 IO，p99 < 1ms）
│         tools/post-execute ──► engine/tool.ts#scanToolResult（凭据 / PII / 注入）
│         tools/result (只观察) ──► 失败计数 + tool_result 账本
├─ 输出:  llm/stream ──► hooks/llm.ts ──► engine/index.ts#evaluateOutput (+ judge/client.ts, 可选 enforce-buffer)
├─ 审批:  approval/request ──► hooks/approval.ts（delegate / policy）
├─ 提示词: system prompt section ──► surface/prompt.ts（只追加，不替换）
├─ 命令:  /safeharness … ──► surface/commands.ts
├─ 设置:  settings 服务 ──► panel/settings.ts + index.ts（loader/volatile-update 热更新）
└─ 面板:  webServer 前缀路由 /safeharness/* ──► panel/route.ts ──► status/patrol/draft/schedule/reload/write-rule/settings/export
```

**分层铁律**（改代码前必须遵守）：

- `src/engine/**` **不许 import 任何 `@deepseek-ai/*` 类型**。hooks 把宿主对象投影成 `ToolView` / `ToolResultView` / `SessionView` 等纯数据，engine 保持可单测、可换实现。
- `ctx.tools.guard` 只能做 O(1) / 有界的同步检查（无 IO、无 await、无 ledger）；异步判定一律放 `tools/pre-execute`。
- 事件接缝注册顺序：四个安全关键面用 `{ prepend: true }`（最佳努力靠前），`ctx.tools.guard` 是**单调兜底**（后面的监听器改不掉它）。文档口径是“prepend 最佳努力 + guard 单调兜底”，不是“保证第一”。
- 拒绝话术固定一句（`runtime.ts` 的 `DENIAL_TEXT` / `TOOL_DENIAL_TEXT` / `RESULT_BLOCK_TEXT` / `OUTPUT_BLOCK_TEXT`），**不回显规则名、参数、阈值**。

## 7. 检测能力现状（逐面）

### 7.1 输入面（`input.mode`）

- 20 条注入规则（`rules/inform.yaml`，`iu` 标志，与内核逐条同源）+ 截断（`maxChars`）+ 清洗（`normalize`）+ 可选语义评审（`judge`）。
- 清洗顺序：**去零宽 → 去 HTML 注释 → NFKC**；清洗后**放行**的回合用清洗文本进入模型（MODIFY，`PreStepDecision.enter` 带改写消息）。
- 结构规则命中即拒（`input_rule_hit`）；危险 SQL 在内容面拒（`input_sql_dangerous`）；评审 `block` → `input_judge_blocked`；无结论 + fail-closed → `input_judge_unavailable`。
- `flagged` 的语义：**只有结构命中且结构本身不拒时**才调评审（精度/成本控制）；结构已拒的回合不再多调一次模型。
- 单测：`tests/input.test.ts`、`input-normalize.test.ts`、`input-judge.test.ts`、`failure-matrix.test.ts`。

### 7.2 工具面（`tools.mode`，pre-execute + guard）

判定顺序（`engine/tool.ts#evaluateToolCall`）：

1. **描述符注入扫描**（`descriptorScan`）：扫工具自己的 name/description（≤8 KiB），命中且 `enforce` → 每次调用都拒（`tool_descriptor_injection`）；`warn` → 每会话每工具记一次 `tool_descriptor_flagged` 后照常执行。
2. `denyTools`（名字 glob）→ `tool_denied_by_name`。
3. `denyTags`（语义标签）→ `tool_denied_by_tag`。
4. 参数字节上限 → `tool_args_too_large`。
5. SQL：只扫“能执行 SQL”的工具（`sqlScan: execution`，R42）；危险语句 → `tool_denied_by_args`；非白名单表 → `unauthorized_sql_table`。
6. 轨迹链（3 条，`rules/chains.yaml`）→ `tool_denied_by_chain`。
7. 重复失败阈值 → `tool_repeated_attempts`（成功清零）。
8. 熵阈值 → `tool_high_entropy_payload`（只记 index/长度/熵值）。
9. `askTools` → `tool_ask_required`。

参数遍历是**迭代 + 循环防护 + 预算**（10 万节点 / 4 MB 字符），超预算 fail-closed deny。

### 7.3 结果面（`results.mode`，post-execute）

- 三类 finding：`credential_leak`（OpenAI key / Bearer / PEM / `key=value` 赋值 / 高熵 token，含 SRI、hex、Windows 路径白名单）、`pii`（内核 10 类，1.12.0）、`injection_marker`（同一套注入规则）。
- 只在 `mode: enforce` 且类别在 `blockOn` 里才 `block`（整个结果被替换，不是只换渲染文本）。
- 扫 256 KiB；finding 只带规则 id 与固定英文描述，**从不带命中值**。

### 7.4 输出面（`output.mode`）

- `warn`：只记 `output_reviewed`；`enforce-buffer`：缓冲整条再裁决（牺牲流式，超时/超限**降级为透传**并记 `labels.buffer`）。
- 可选 judge（默认关）：`scope: flagged` 只审已被规则命中的回答；judge 自己的调用带 `[safeharness-judge]` 标记，不会被再次评审（递归防护）。

### 7.5 审批桥（`approval.mode`）

- `delegate`：完全交给宿主对话框；`policy`：按粗粒度规则（一次性放行、拒绝即不可再决）裁决。
- 账本：`approval_asked` / `approval_decided`；巡检用它们做对账（`ledger_reconcile`）。

### 7.6 审计 / 姿态 / 巡检 / 预算 / 起草

- **审计**：NDJSON，单行一记录，字段级脱敏（content→sha256、长度、键名），可选哈希链（`prev_sha256`），按大小轮转；`audit.required = true` 时账本不可写 → 执行面 deny。
- **姿态 10 项**：`sandbox_danger_full_access`、`approval_never`、`hmr_enabled`、`rules_loaded`、`ledger_writable`、`ledger_chain_ok`、`output_guard_off`、`judge_unavailable`、`plugin_version_mismatch`、`engine_sidecar_unavailable`。`posture.failOn` 里任一 FAIL → `apply()` 抛错拒绝加载。
- **巡检 5 项**：`audit_rate`、`health_probe`、`config_drift`、`ledger_reconcile`、`notify`；退出码 0/1/2；**巡检函数从不抛异常**。
- **预算**：`budget.maxTokensPerTurn > 0` 按轮累计，越限只 warn（每回合一条）。
- **起草**：只产出草稿（`applied: false`），**从不落盘**；落地要么人工放进 `rules.dir`/`inline`，要么面板 1.9.0 起的「写入并重载」（§11.4）。

### 7.7 模型可见工具（5 个，全部只读）

`safeharness_status`、`safeharness_posture`、`safeharness_patrol`、`safeharness_audit_query`、`safeharness_draft_rule`（起草不写盘）。

### 7.8 命令

### 7.9 账本 kind 词表（`audit/types.ts`，21 个）

## 11. 规则体系

### 11.1 文件与优先级

`rules/inform.yaml`（20 条 deny 规则）+ `rules/chains.yaml`（3 条链）。加载顺序：**包内 < `rules.dir` < `rules.inline`**，同名高层覆盖低层；`rules.watch` 监听 mtime 热更新，失败保留旧集合 + 记 `rules_reloaded`/日志。

### 11.2 规则写法

```yaml
rules:
  - name: snake_case_unique
    pattern: '正则（JS 兼容子集；Python-only 语法会被拒绝）'
    severity: critical|high|medium|low|info
    category: prompt_injection
    action: deny            # v1 只支持 deny
    reason: 人读的一句话
chain_rules:
  - name: read_then_egress
    first: 'read_*'          # 名字正则
    then: 'web_*'
    first_tags: [fs]         # 或标签
    then_tags: [egress]
    max_gap: 0               # 0 = 任意距离
    severity: high
    category: trajectory_chain
```

### 11.3 加载门（写前校验）

`validateRuleCandidate()` 用**真实 loader** 把“候选 + 包内 + dir + inline”整体编一遍；编不过就**一个字节都不写**。Python-only 正则、同名重复、坏 severity/action、**嵌套量词（`(a+)+` 这类 ReDoS 形状）** 都由 loader 拒绝。1.14.2 起 `NESTED_QUANTIFIER` 是 loader 的硬门（定义在 `engine/rules.ts`，起草路径 import 同一份），`rules.dir` 手写文件与 `rules.inline` 一样拦；只拒"组内无界量词 × 组外无界量词"，`(\d{3}){2}` 这类有界嵌套仍可加载——见 §12.2-11。

### 11.4 面板写路径（D62 的窄口）

只写 `rules.dir`（不写包内；解析进包内/历史目录会拒）；文件名 `^[a-z0-9][a-z0-9._-]{0,63}\.ya?ml$`；默认不覆盖（`rule_exists`，第二次显式 `overwrite:true`）；临时名不以 `.yaml` 结尾（watcher 不会读到半成品）；原子 rename；账本只记文件名/字节/计数。

### 11.5 快照与回滚（1.14.0）

- 目录：`$DSH_HOME/safeharness/rules-writes/history/<id>/`（`id = YYYYMMDDTHHMMSSZ-<n>`），含 `manifest.json`（每文件 bytes+sha256）。
- 保留 **10** 份；`capture` 上限 64 文件 / 单文件 256 KiB，超限跳过并告警。
- 触发：`write`（面板写入前）、`pre-rollback`（回滚前自动，使回滚可反悔）。
- 回滚顺序：校验 id → 校验每文件 sha256（不符拒）→ 临时目录跑真实 loader（编不过拒）→ 拍 `pre-rollback` → 原子写回 + 删快照外 `.yaml/.yml` → 热重载（失败只报 `reloaded:false`）。
- **它不是什么**：不是版本库（无 diff/分支），不是备份（`$DSH_HOME` 删了就没了），不覆盖手工改文件。

## 12. 已知弱点与坑（诚实清单）

### 12.1 与内核的口径差异（都写在 MANUAL，别偷偷改）

1. 输入评审：内核 UNCERTAIN 一律拒，插件默认 fail-open（避免没配 judge 的 profile 全挂）。
2. 描述符扫描：内核在 `list_tools` 下架工具，插件逐次拒绝（宿主无下架接缝）。
3. SQL 白名单：内核内容面也算，插件只算工具参数面。
4. PII：内核是记忆写入的脱敏/拒绝，插件落在工具结果面且**默认不拦**（要拦得把 `pii` 加进 `blockOn`）。
5. 链端点匹配：插件 OR，内核 AND（更严）。
6. 规则版本：内核 DB“只增不减 + 10 版”，插件目录快照（可被覆盖、可手工改）。

### 12.2 技术坑（都真实踩过）

1. **pnpm store 主版本**（§3）：profile 只能由 DSH 自带 pnpm 写；`ERR_PNPM_UNEXPECTED_STORE` → 删 `node_modules` 用 `dsh plugin add` 重建。
2. **PII 邮箱正则的二次回溯**：内核 `[A-Za-z0-9_.+-]+@…` 在 256 KiB 结果上单次扫描 **111 秒**；已加 RFC 长度上界（本地 64 / 标签 63），回到毫秒级。**给 PII/凭据类加正则时必须用长文本跑一次性能测试**（`tests/perf.test.ts`）。
3. **Windows 上 `.NET` 相对路径以仓库根为 CWD**；`Get-Content -Raw | Set-Content` 会把中文写坏（丢过 500 行 MANUAL）。改文本用编辑工具或 `.NET`+UTF8 无 BOM 绝对路径。
4. **发布时的 CRLF 噪声**：公开仓 worktree 必须先 `git config core.autocrlf false` + `core.eol lf`，并在 `git add -A` 前把工作树 CRLF 归一化为 LF，否则 70 个文件假 diff。
5. **GitHub 推送不稳**：用 `git -c http.version=HTTP/1.1 push` + 重试循环（5–6 次）；`-c` 必须放在子命令**前**。
6. **本插件自己的结果守卫会拦工具回显**：当读/写的内容里出现模式名、`key` 之类字符串时，`read`/`grep`/`pwsh` 的结果可能被 `tool_result_flagged` 拦截显示（`results.mode: enforce`）。操作其实已经执行——用更小的读取窗口、`Select-String` 窄模式、或 `Test-Path`/`Contains` 二次确认来核对。
7. **`npm pack` 默认写 CWD**，要用 `--pack-destination dist`（否则 tgz 落在包根）。
8. **`approval_never` 无法作为加载门禁**：0.2.2 上审批策略没有无 session 的读取器，hardened 的 `failOn` 故意不含它（会 SKIP，永远不触发）。
9. **`ctx.tools.get()` 只保证 `description`**：参数 schema 校验必须自己从 `ToolDefinition.parameters` 拿（§16.1）。
10. **sidecar 只做输入面**：`engine.kind: sidecar` 是可选 Python 输入引擎，不影响工具/结果/输出面；本机未启用。
11. **ReDoS 形状是加载门（1.14.2 起，此前是缺口）**：输入面在 `agent/pre-step` 里**同步**执行，JS 正则开始回溯后无法中断，所以 `(a+)+` 形状必须挡在加载前。1.14.2 把 `NESTED_QUANTIFIER` 下移到 `engine/rules.ts` 的 `checkRegex`（`compileRule` / `compileChain` / `rules.dir` / `rules.inline` 四条入口一致拒绝），`draft/rule.ts` import 同一份定义，不再各写一套。**边界**：只拒"组内无界 × 组外无界"，抓不住 `(a|aa)+` 交替爆炸，也不拒 `(\d{3}){2}` 有界嵌套（多项式）——见 MANUAL §11 第 21 条。若要再进一步，可加"编译耗时上限"或对 `(a|aa)` 形态做静态检测，但收益边际、误杀风险上升。
12. **宿主 rc 小版本升级会让 hardened 直接拒载**（2026-11-19 真实踩到）：桌面版 0.2.2-rc.3 → 0.2.2-rc.5 后，`plugin_version_mismatch` 立即成立，而该 code 在 `hardened.posture.failOn` 里——`balanced` 只是 WARN，`hardened` 直接拒绝加载。1.14.1 的修法是把版本门拆成 **`PINNED_VERSIONS`（当前钉住）+ `PREVIOUSLY_VERIFIED_VERSIONS`（曾实测、仍接受）** 两表，并加 `tests/host-versions.test.ts` 钉住行为。**下次宿主升级的固定动作**：`safeharness_status.host` 看实际解析版本 → 更新 `PINNED_VERSIONS` → 把上版加进 `PREVIOUSLY_VERIFIED_VERSIONS` → 在 host-versions 测试里加一条“旧宿主仍可载”。不要靠放宽成区间匹配（那等于把没测过的版本也当支持）。
13. **凭据正则的三个坑**（2026-11-19 真实事故：模型把用户中转站 key 打在回答里）：① `\b` 会挡住长标识符后缀（`LLM_API_KEY` 里的 `API_KEY` 前是 `_`），JSON 键名后还多一个引号——两者叠加让 `"LLM_API_KEY": "…"` 整条漏过结果守卫，模型因此拿到了 key；② **输出面此前只跑注入规则、没有凭据扫描**，`warn` 又只记账，所以回显 key 的回答被记成 `rule_ids: []`、`allow`——账本干净、屏幕泄漏；③ 形态正则的前缀一旦无界（`[A-Za-z0-9_$-]*`）会在 256 KiB 输入上退化成灾难性回溯，直接卡死整套测试。1.15.1 的修法：三面共用 `scanCredentialLeaks`、前缀加上界（32）+ key-ish 词预筛、`warn` 流内脱敏（256 字符尾部窗口，重写 `block-end`，账本记 `labels.redacted`）。**新加任何凭据/PII 正则都必须**：跑一次 256 KiB 对抗性长文本、并想清楚 JSON 引号/长标识符/跨 chunk 三种形状。

## 17. 决策记录（为什么是现在这样）

| 决策 | 理由 |
|---|---|
| D62：面板写路径只允许 `rules.dir`、文件名白名单、默认不覆盖、写前 loader 门、原子写 | 规则集是信任根；模型没有写工具，必须人点按钮 |
| 输入 judge 默认 fail-open，hardened fail-closed | 没有评审路由的 profile 恒 fail-closed 会让每一轮输入都被拒 |
| 描述符 `enforce` = 逐次拒绝 | 宿主没有“从模型工具表下架工具”的接缝；warn 按会话去重避免刷账本 |
| PII 落结果面且默认只告警 | 没有记忆库；对结果做自动改写会破坏证据 |
| 规则版本用目录快照而非 DB | 零依赖、可离线；代价是没有 append-only 与 diff |
| 链端点匹配用 OR | 任务规格要求；比内核 AND 更严，fail-closed |
| 高熵阈值默认 0（关） | 与内核一致：装上去不改变行为，运营商显式开启 |
| 预算只 warn | 宿主没有可靠的 token 计量；硬拦会误伤 |

## 18. 快速排障表

| 症状 | 原因 | 处理 |
|---|---|---|
| 插件页只有 README、没有工作台 | 浏览器半侧没注册 `plugins.bundle.config` / 包不是 bundle | 确认 `package.json` 有 `dsh.bundle.patch`；重装；看 `tests/client-bundle.test.ts` 的断言是否被破坏 |

| `seams.* = false` | 该 profile 没提供对应宿主能力 | 正常；看 `safeharness_status.seams` 与 MANUAL §4.7 |

| `judge_unavailable` 姿态 FAIL | 没配 `output.judge.provider/model` 或无 `ctx.llm` | 面板「语义评审」选路由 + 探针；hardened 会拒绝加载 |

| 面板 405 | 用了 GET | 全部端点 POST-only |

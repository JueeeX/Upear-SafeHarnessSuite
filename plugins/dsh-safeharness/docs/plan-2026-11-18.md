## 2. 移植计划

### P0（先让"拦得住"与内核一致，1.11.0）

1. **输入归一化 + MODIFY**
   - 判定前做：NFKC、去零宽字符、去 HTML 注释；规则仍按原文本命中。
   - 语义：内核命中即 DENY；仅"清洗后可放行"才 MODIFY。DSH 的 `agent/pre-step` 决策是 `{ kind: 'enter', messages: UserMessage[] }`，**可以带改写后的消息**，所以 MODIFY 可直接实现（清洗后的文本替换原消息，账本只记 `input_normalized` + 字符数差）。
   - 验收：新增单测覆盖零宽拆分关键词（`ig\u200bnore`）、全角 NFKC、HTML 注释藏指令；改写后文本必须与原文本一致时才走 enter，否则 deny。
2. **输入面语义 judge**
   - 复用现有 `output.judge` 路由（provider/model/timeout），新增 `input.judge: off | flagged | always` 与 `failClosed`。
   - 内核口径：`INJECTION` / `UNCERTAIN` / 错误一律拦；插件默认 `flagged + failClosed=false`，`hardened` 预设强制 `failClosed=true`。
   - 成本与延迟写进面板提示（每轮多一次模型调用）。

### P1（补齐内核检测面，1.12.0）——已完成

3. ✅ **SQL 形状分类 + 表白名单**：形状分类 1.1.x 已在 `engine/sql.ts`；1.12.0 补 `tools.sql.allowedTables`（空=不限制）、`unauthorized_sql_table` 与注释剥离回归（`DEL/**/ETE` 已有用例）。
4. ✅ **工具描述符扫描**：`tools.descriptorScan: off/warn/enforce`，扫 `name`+`description`（≤8 KiB），`warn` 每会话每工具记一次 `tool_descriptor_flagged`，`enforce` 每次调用拒。
5. ✅ **PII 类别对齐**：内核 10 类逐条同名进结果面（`category: pii`），`results.pii` / `results.piiClasses` 可按类开关，默认只告警。
6. ✅ **轨迹阈值**：`tools.repeatedAttemptThreshold`、`tools.entropyThreshold` + `entropyMinLength`（默认 0=关闭，与内核一致）。

### 热修（1.15.2，2026-11-20 已完成）

11. ✅ **面板保存回归**（1.13.0 起零成功保存；1.15.2 修）

    - 测试：此前保存路径**零测试**。新增纯逻辑 8 条（`tests/settings-form.test.ts`）+
      jsdom 真挂载 5 条（`tests/panel-settings.test.tsx`：控件→dirty→点保存真发出
      `{expectedRevision, judge:{scope}}`）；58 文件 / 882 用例。
    - 待真机确认：重启后在面板点一次保存，账本应出现**面板来源**的 `panel_settings`

## 4. 验收与纪律

- 每条移植都要有：单测（行为对齐内核口径）＋ 账本字段/理由码 ＋ MANUAL 与 CHANGELOG 更新。
- 公开树测试口径：1.11.0 为 47 文件 / 767 用例；1.12.0 为 51 文件 / 821 用例；1.13.0 为 51 文件 / 825 用例；1.14.0 为 52 文件 / 843 用例。新增用例不减少。
- 面板写入沿用 revision CAS；每个阶段做一次真机验证（重启后点得到、改得动、可回滚）。
- 版本节奏：1.11.0 = P0 + 面板阶段一；1.12.0 = P1 + 阶段二首批（SQL 白名单、PII、阈值）；1.13.0 = 阶段二余项 + 阶段三 + 档位对照；1.14.0 = 规则目录版本回滚（计划内最后一版）。

## 5. 明确不做

记忆/embedding、租户、PG 审计 sink、工具网关回执与重放、管理面受控变更、进化闸门、OS 沙箱实现、外部智能体监督器——这些要么内核尚未完成，要么属于宿主/服务端形态，插件只记录边界，不复制。

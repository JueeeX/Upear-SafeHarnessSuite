## 6. 本轮做了什么（1.14.1 → 1.15.2，逐版）

### 6.1 1.14.1（2026-11-19）宿主 rc.5 兼容

- 症状：桌面版升到 `0.2.2-rc.5`，插件 `PINNED_VERSIONS` 还钉 `rc.3`
  → `plugin_version_mismatch` 恒成立；该 code 在 `hardened.posture.failOn` 里，
  **切 hardened 直接拒绝加载**（balanced 只 WARN，所以桌面档一直没暴露）。
- 修法：`PINNED_VERSIONS`（rc.5）+ `PREVIOUSLY_VERIFIED_VERSIONS`（rc.3，实测仍接受）
  两表，`acceptableVersions()` 合并；表外版本仍按 WARN/FAIL，拒绝理由里列出可接受版本。
- 测试：`tests/host-versions.test.ts` 4 条。
- 发布：主仓 `7de386f`、公开仓 `a67847d` + `v1.14.1`。

### 6.2 1.14.2（2026-11-19）loader 的 ReDoS 门

- 输入面在 `agent/pre-step` 里**同步**跑规则，JS 正则一旦灾难性回溯就无法中断。
  旧行为只在**起草路径**检查嵌套量词，手写规则文件绕过这道门。
- 修法：`engine/rules.ts` 导出 `NESTED_QUANTIFIER`，`checkRegex` 增加第 4 道门，
  `compileRule` / `compileChain` / `rules.dir` / `rules.inline` **四条入口一致拒绝**
  无界嵌套（`(a+)+`、`(.*)*`）；有界嵌套（`(\d{3}){2}`）不误杀。
- 测试：`tests/rules-redos.test.ts` 7 条；发布 主仓 `d873611`、公开仓 `2e2b7d3` + `v1.14.2`。

### 6.3 1.15.0（2026-11-19）`rules check` + 文档

- `/safeharness rules check [dir]`：用重载路径**同一个** `tryLoadRuleSet`
  （packaged + dir + inline）跑一遍；通过打印合并条数，失败逐条 problem（≤10 + 余数）；
  目录不存在是**错误**而不是空通过；只读，不写盘/不重载/不记账本。
  与内核 `rules_check.py` 的差别：命令没有进程退出码，`kind: error` +
  首行 `rules check: failed (...)` 就是自动化可判的失败信号。
- `packagedRulesDir()` 收进 `util/packaged.ts`（装配根与命令面共用一份）。
- MANUAL §8 新增「明确不移植的内核 policy」表（`verify`/`correct`/`intent`/`lifecycle`）。
- 测试：`tests/rules-check.test.ts` 6 条；发布 主仓 `cbd28ea`、公开仓 `3436116` + `v1.15.0`。

### 6.4 1.15.1（2026-11-19）真事故：模型把 key 打印进了回答

- 事故：`session-2242f394`，用户问「我中转站的 key 是多少」，模型读配置后把一条
  **14 字符的真 key** 打进回答。当时账本记的是 `output_reviewed allow / rule_ids: []`。
- 根因两处：
  1. `credential_assignment` 的 `\b` 挡住长标识符后缀（`LLM_API_KEY` 里 `API_KEY` 前是
     `_`），且不允许 JSON 键名后的引号 → `"LLM_API_KEY": "…"` 整条漏过工具结果守卫，
     key 进了模型上下文；
  2. 输出面只跑 20 条注入规则，**完全没有凭据扫描**；`warn` 又只记账 → 回答原样透传。
- 修法：
  - 三面共用 `scanCredentialLeaks()`（工具参数 / 工具结果 / 模型输出），正则允许键名后
    引号、允许 ≤32 字符标识符前缀、对引号值排除 `z.string()` / `process.env.X` 这类引用；
  - 输出面命中即 `deny`（`ReasonCode.CredentialLeak`，category `credential_leak`），
    `enforce-buffer` 整条替换；
  - **`warn` 也在流里脱敏**：256 字符尾部窗口覆盖跨 delta 拆分的密钥，重写 `block-end`
    的权威文本，账本记 `labels.redacted=credential` + `metrics.redacted_count`；
  - 性能：前缀加上界 + key-ish 预筛（无界前缀曾在 256 KiB 输入上灾难性回溯，整套测试
    卡死数分钟）；`tests/perf.test.ts` 加对抗用例（256 KiB 最坏 31.8 ms）。
- 用真实会话日志**复放**：命中两处工具结果（只打印命中 id，不打印凭据）。
- 边界（诚实口径）：形态检测不是真值保证——自定义短 token、拼接字符串、超过窗口的长
  令牌仍可能漏过；真正的边界是「真密钥不进 prompt/工具结果」。
- 发布：主仓 `51885c0`、公开仓 `81a8b66` + `v1.15.1`。

### 6.5 1.15.2（2026-11-20）设置页「一次也保存不了」

**症状**：用户改了下拉/数字，底部保存条仍显示「没有修改」，保存按钮一直灰着。

**根因（一句话）**：`buildPatch` **从来没产出过 patch**。
`nonNegativeNumber` 当初只为「熵阈值」而写，把 `[0, 8]` 上界**硬编码在函数体里**；
1.13.0 让巡检字段（`patrolWindowMinutes` / `patrolFactor`）共用它之后，
**默认值 10 分钟**直接落在界外 → 函数在构建 patch 之前就返回 `invalid`。
默认表单即非法 ⇒ **任何**字段都存不下去；真正的理由（「巡检窗口必须是 ≥ 1 的分钟数」）
渲染在保存条**下方**，被漏看。

### 6.6 1.16.0（2026-11-20）工具参数形状规则

**做了什么**：把内核 `constrain.py` 的 argument-schema 那一半（`_schema.py#validate_arguments`）
搬过来——`tools.argSchemas` 声明"某个工具的参数必须符合某种形状"，越界即
`unauthorized_tool_argument`。这不是新语义，是 §9.1 里 `constrain.py` 从「🟠 一半」变成
「✅ 参数 schema 部分」的那一笔。

**六种原语**（全部线性时间可判定，**不引 JSON Schema 全集**）：`pattern` / `enum` /
`minBytes` / `maxBytes` / `pathPrefix` / `urlScheme` / `commandAllowlist`。
三条不是"顺手加的"，是朴素写法会漏：

1. `pathPrefix`：单纯前缀匹配放行 `/workspace/../../etc/passwd`（归一化后是 `/etc/passwd`）
   与 `/workspace-evil/x`（文本上以 `/workspace` 开头）。改成任何 `..` 段直接拒 + 按段比较
   + `\` 归一。
2. `commandAllowlist`：`"git status; rm -rf /"` 的第一个 token 是白名单里的 `git`。
   改成先查 shell 元字符（`; & | \` $ < > ( ) { }` 与换行）+ 拒前置赋值（`LD_PRELOAD=x git`）。
3. 关键字集合是**闭合**的：`regex:` 写成 `pattern:` 会被报错，而不是编译成一个什么都不
   检查的 schema（1.15.2 教会的事：静默的"没生效"比报错贵）。

**判定位置**：`tools/pre-execute` 第 (4b) 步，排在 `denyTools`/`denyTags`/参数字节上限/SQL
之后、轨迹链之前。`denyTools` 与 SQL 先赢（操作者看到最直接的理由）；同一工具**第一条**
匹配的 schema 生效；只约束**实际传了**的参数；文本约束落到非字符串值上 → fail-closed。

**失败方向**：某一条编译不过 → **只丢这一条** + 姿态第 11 项 `arg_schema_invalid`（WARN，
默认不进 `failOn`）。一个可选 schema 的笔误不该让插件起不来，但绝不静默。

**性能**：schema 正则面对的是最长 `tools.maxArgsBytes`（64 KiB）的模型可控文本，和规则
文件是同一个 ReDoS 面 → `pattern` 复用 `engine/rules.ts#checkRegex`（Python-only 构造、
全局内联标志、无界嵌套量词三道门一致）。

**测试**：`tests/arg-schema.test.ts` 39 条 + `tests/posture.test.ts` 2 条 + `tests/perf.test.ts`
1 条 → **59 文件 / 924 用例**（此前 58 / 882），双 `tsc` 0 错，`npm pack` 出
`upear-dsh-safeharness-1.16.0.tgz`（413 KB / 156 文件，运行时仍零第三方依赖）。

**发布**：主仓 `fe80104`（已推 `github/main`）；**公开仓 `v1.16.0` 未发布**。

**踩过的坑（值得单独记一笔）**：新增的 perf 用例第一版跑 400×5 次 × 64 KiB，`maxBytes`
每次都要重新编码该值，整条用例分配约 128 MB，**把 GC 停顿推给了它上面几行的
`scanToolResult` 预算**（全量 4 次里 3 次失败；Stash 掉改动后在未污染的树上 4 次里 1 次
失败，所以不是纯环境噪音）。改成 16 KiB × 100 次、并放到测试文件最后，4 次全量全绿。
预算用例的规模本身就是被测系统的一部分。

## 7. 架构：接缝、装配顺序、五个面

### 7.1 宿主接缝（共 6 个事件 + 1 个同步 guard + 服务注入）

| 接缝 | 用途 |
|---|---|
| `agent/pre-step` | 输入面：判定 + 归一化（MODIFY 改写消息）+ 输入语义 judge |
| `tools/pre-execute` | 工具调用面：deny / ask；参数形状、SQL、轨迹链、描述符扫描 |
| `tools/post-execute` | 结果面（结构化结果）：PII / 凭据扫描，可改写结果 |
| `tools/result` | 结果观察面：记录 `tool_result_flagged`（不参与决策） |
| `llm/stream` | 输出面：流式缓冲、`enforce-buffer` 整条替换、`warn` 流内凭据脱敏、可选语义 judge |
| `approval/request` | 审批桥：`delegate`（透传）/ `policy`（按粗粒度规则裁决） |
| `ctx.tools.guard(...)` | **同步**、无 IO、有界的第二道工具闸（异常即 deny） |
| `ctx.inject(['settings'])` | 用 `ctx.inject` 顺序安全地读 `settings`（load 瞬间 `ctx.get('settings')` 恒 undefined） |
| `inject = ['tools','systemPrompt']` | 插件启动前必须就绪的两个服务；缺一个就「静默不启动」 |

只读面：5 个工具（`safeharness_status` / `_posture` / `_patrol` / `_draft_rule` /
`_audit_query`）、命令 `/safeharness status|posture|rules [check [dir]]|audit [n]|patrol
[check…]|judge [probe]|draft …|reload`、系统提示词条款、invariant companion（`./invariant`）、
面板 4 个槽（见 §14）。

### 7.2 装配顺序（`src/index.ts`）

配置 → judge/LLM 门禁 → 规则加载 → 账本 → 运行时 → 宿主面探测 + `plugin_loaded` +
姿态门禁 →（**硬门禁失败就在注册任何监听器之前** `return`，不留半装配）→ 提供服务 →
注册各面 → 工具/命令/设置面探测 → 规则监听（`rules.watch`）。

### 7.3 五个防护面与三档预设

面：`input`（输入）/ `tools`（工具调用）/ `results`（工具结果）/ `output`（模型输出）/
`approval`（审批桥）。

每面取值：input/tools/results = `off|warn|enforce`；output = `off|warn|enforce-buffer`；
approval = `policy|delegate`。

预设（`preset`，会被 `resolveConfig` 展开成每面默认值，深冻结）：

| 预设 | 语义 | 失败方向 |
|---|---|---|
| `observe` | 全 warn/off，只记账 | fail-open |
| `balanced` | 默认；input/tools/results enforce，output warn，审批透传 | 面内 fail-closed（异常即 deny），judge 失败 fail-open |
| `hardened` | 更严；output `enforce-buffer`；`posture.failOn` 含关键码（拒载）；输入 judge fail-closed | fail-closed |

**注意**：`preset` 只在 profile patch 里改（面板不写它）；面板的「逐面开关」是**逐字段
覆盖**，只写动过的字段，`preset` 保持原值。

### 7.4 判定分层（读代码的顺序）

1. `src/engine/**`：**纯函数**（无 DSH import）——`rules`（规则/链编译与匹配）、`input`、
   `sql`、`tool`（形状/凭据/PII）、`types`。可单测、可移植。
2. `src/hooks/**`：DSH 事件签名 → 纯函数的薄适配层（input/tools/llm/approval/context）。
3. `src/judge/**`：语义 judge（零依赖 HTTP，超时/坏 JSON/空回答/递归防护）。
4. `src/audit/**`：NDJSON 哈希链账本（脱敏、轮转、路径解析）。
5. `src/posture/**`、`src/patrol/**`：姿态 10 项 / 巡检 5 项（永不抛异常）。
6. `src/panel/**` + `src/client/**`：面板宿主半 + 浏览器半。
7. `src/runtime.ts`、`src/budget.ts`、`src/config.ts`、`src/state.ts`、`src/version.ts`。

姿态 10 个码：`sandbox_danger_full_access`、`approval_never`、`hmr_enabled`、
`rules_loaded`、`ledger_writable`、`ledger_chain_ok`、`output_guard_off`、
`judge_unavailable`、`plugin_version_mismatch`、`engine_sidecar_unavailable`。

巡检 5 项：`audit_rate`（拒绝率）、`health_probe`（外部健康端点）、`config_drift`
（与上次 `posture_report` 的漂移）、`ledger_reconcile`（哈希链对账）、`notify`（通道）。

## 9. 与内核（Upear Python）的对比

### 9.1 内核 `policies/` 的 8 条策略：**对齐 4 条 + 1 条已对齐 + 1 条参数 schema 已对齐**

| 内核策略 | 插件 | 说明 |
|---|---|---|
| `inform`（20 条结构注入规则 + 归一化 MODIFY + 语义复核） | ✅ | 20 条规则逐条同源；1.11.0 起 NFKC/零宽/HTML 注释清洗后可放行（MODIFY）；输入语义 judge 与内核口径差异写在 MANUAL §4.9 |

| `trajectory`（链 A→B + 重复阈值 + 熵阈值） | ✅ | 链 3 条 + `repeatedAttemptThreshold` + `entropyThreshold`（默认 0 = 关，与内核一致） |
| `rules_check.py`（部署期规则目录校验） | ✅（1.15.0） | `/safeharness rules check [dir]`，同一个 loader，只报告不落盘 |
| `constrain.py`（工具目录 + 能力 + **参数 schema 校验**） | 🟠 **参数 schema 已对齐（1.16.0），目录/能力仍近似** | 参数 schema：`tools.argSchemas` + `engine/argschema.ts`（六种原语，`pattern` 走 loader 的 ReDoS 门）。目录/能力那半仍是 `denyTools`/`denyTags`/`tagOverrides` 近似——`ToolCatalog`（签名目录）与 `CapabilityAuthority`（能力票据）是跨进程语义，和 `intent.py` 一样不移植（MANUAL §8） |
| `verify.py`（分层动作验证：verifier 注册表 + 裁决等级） | ❌ | DSH 决策面只有 allow/ask/deny，没有 verifier 注册表或等级语义；硬做=发明协议 |

- **PII 10 类**（`memory/sanitizer.py`）→ 结果面 `results.piiClasses`，逐条同名，默认只告警；
- **MCP 描述符注入扫描**（`llm/safeharness_mcp_guard.py`）→ `tools.descriptorScan`

- **审计脱敏**（`runtime/redaction.py`）→ 内容 sha256 + 敏感键 + 16KB 截断 + 轮转 + 链；
- **姿态 10 项 / 巡检 5 项**（`posture_check.py` / `deploy_patrol.py`）→ 同名同义。

### 9.2 明确不移植（服务端/宿主形态）

工具网关与 HMAC/Ed25519 回执、重放库、PG 审计 sink、多租户、`admin_ui/` + 受控变更
（重认证/幂等键）、`evolution/content_gate.py`、`communication/`（智能体间消息）、
审批 TTL/approver（宿主对话框托管）、OS 沙箱实现（宿主 `sandboxPolicy`）、
运维面（health_detail / chat_bridge / coordination_cli）。

**判断标准**：内核里「需要跨进程 / 数据库 / 管理面才能成立」的能力，一律不搬；
写清楚「为什么不成立」比假装做了更有价值（MANUAL §8 有完整表）。

### 9.3 为什么必须重写而不是调 Python

DSH 的 agent loop 在 Node 进程内，安全钩子必须在同一次调用栈同步/异步返回 allow/deny。
Python 侧是独立进程/服务，无法在 `tools/pre-execute` 返回前完成判定；即使能，也引入
IPC 延迟，且覆盖不了同步 `ctx.tools.guard()`。所以把需要的判定**逐个移植为纯函数**，
保持与 Python 引擎相同的规则语义，同时保持运行时零依赖。
（可选 sidecar `engine.kind: sidecar` 是另一条路：让 Python 参与输入面判定，但不是默认。）

## 13. 坑与铁律（每条都踩过）

1. **PowerShell 5.1 会把 UTF-8 文件读成 GBK**：`Get-Content -Raw` / `Set-Content`
   处理中文源码会造成**整文件乱码**（本轮曾把 `panel.tsx` 写花，靠 `git checkout` 救回）。
   改文件优先用编辑器工具（read/edit/write）；必须用脚本时走
   `[System.IO.File]::ReadAllText / WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`，
   并且**用绝对路径**（.NET 的当前目录是进程 CWD，不是 PowerShell 的 `cd`）。
2. **文件可能被工具整篇重写成 CRLF**：本仓 `.gitattributes` 是 `* text=auto eol=lf`，
   `git diff` 会提示「CRLF will be replaced by LF」。提交前统一：
   ```powershell
   $t=[System.IO.File]::ReadAllText($p); if($t.Contains("`r`n")){ $t=$t -replace "`r`n","`n"; [System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false))) }
   ```
   复核：`git diff --ignore-cr-at-eol --stat`（只应剩真实改动）。
3. **PowerShell 没有 heredoc**：`git commit -F - <<'MSG'` 会报语法错。把消息写成 UTF-8
   文件再 `git commit -F 文件`。
4. **`Invoke-WebRequest` 在本会话非交互模式下会报「朗读和提示功能不可用」**（走 IE 引擎）
   → 用 `curl.exe`；`[System.Net.Http.HttpClient]` 在本机 PowerShell 里没有该类型。
5. **esbuild 输出 ASCII 转义**：`lib/client.js` 里的中文是 `\uXXXX`，`Select-String` 查
   中文会假阴性；查 ASCII 标记（函数名/数值）或 `node -e` 读文件。
6. **pnpm 祖先 `packageManager` 陷阱**：`C:\Users\xiaojue\package.json` 声明 `yarn`，
   在没有 `package.json` 的目录里跑 DSH 自带 pnpm 会直接报错。装插件时把 cwd 切到
   profile 目录。
7. **插件自己的守卫会拦你的测试数据**：工具结果/输出里出现凭据形状的字符串（哪怕是
   测试用的假 key）会被本插件拦下或脱敏。**测试里把假 key 运行时拼出来**
   （如 `['yXcX','Abc123','XpJ'].join('')`），不要写字面量。
8. **judge 有递归防护**：请求带 `[safeharness-judge]` 标记 + 内部 Symbol，`llm/stream`
   看到就跳过；judge 永远不会评审自己。判 `block` 在 `warn` 下只记账（流已发出，撤不回），
   `enforce-buffer` 才整条替换。
9. **账本轮转 64 MB**：`ledger.ndjson` 已超 10 MB，别整份读进内存分析；用
   `Select-Object -Last N` 或按 `seq` 定位。
10. **改 Profile JSON 要看两处**：`cordis.patch.yml` 里可能同时有 `safeharness` 的
    `config` 块与 `append-safeharness-block.ps1` 维护的不变量段；手写
    `config` 是**整段替换**而不是深合并，只写 `judge` 会让 `providers` 消失（桌面主对话
    模型随之不可用）。
11. **主项目 pytest 的 TMP 坑**：`F:\AgentSecurity\Upear` 下跑 pytest 会因
    `pytest-current` 权限失败，先 `$env:TMP='F:\tmp\pytest-tmp'`。

### 14.1 槽位（浏览器半注册）

|---|---|---|

### 14.2 端点（**全部 POST-only**，`GET` 返回 405 + `Allow: POST`）

| 端点 | body | 说明 |
|---|---|---|
| `/safeharness/status` | `{}` | 概览载荷（会话/规则/计数器/账本健康/事件窗口） |
| `/safeharness/patrol` | `{}` | 跑一次巡检，返回 5 项结果 |
| `/safeharness/draft` | `{description}` | 让起草路由生成候选规则（不写入、不启用） |
| `/safeharness/schedule` | `{op:'read'|'arm'|'disarm', intervalMinutes?}` | 定时巡检（状态落 `panel-state.json`） |
| `/safeharness/reload-rules` | `{}` | 重读规则目录 |
| `/safeharness/write-rule` | `{op:'write'|'history'|'rollback', …}` | 草稿落地 / 快照列表 / 回滚（1.14.0） |
| `/safeharness/settings` | `{op:'read'|'save'|'probe'|'add-provider'|'delete-provider', …}` | 面板读写；`save` 带 `expectedRevision` |
| `/safeharness/export` | `{limit?}` | 账本片段（≤500 条，已是脱敏记录） |

栅栏：**只接受 loopback Host + 同源 Origin**（带跨站标记直接拒），body ≤ 16 KiB，
单飞/冷却，写端点带 revision CAS。响应是固定投影：只有代码/名称/哈希/计数/短 id/路径，
**不含** prompt、参数原文、模型输出、webhook 或凭据。curl 没有 Origin 头，因此能调——
这是设计（本地诊断），不是漏洞；但它确实意味着**本机任何进程**都能读面板数据，别在
多用户机器上这么用。

### 14.3 设置页保存条（1.15.2 之后的语义，改之前先读这段）

```
dirty  = buildPatch(value, form).patch !== undefined || .invalid !== null
按钮禁用 = !dirty || invalid !== null || readOnly || saving
readOnly = !value.judge.configurable
```
- `buildPatch` 是纯函数（已导出，供测试）：逐字段 diff，只把动过的字段放进 patch，
  并回传 `expectedRevision`（宿主 patch 修订号，进程重启后归 0）。
- 非法值也是「有未保存的修改」，理由显示在**保存条内**；按钮 `title` 说明原因。
- 草稿（未保存的表单）写 `sessionStorage`，键 `safeharness.panel.settings-draft`，
  带 `baselineOf(value)`；基线**只含可编辑字段**，探针状态翻转不会清草稿。
- 保存成功写 `safeharness.panel.settings-saved`，宿主重载导致面板重挂时用它继续显示
  「已保存」（15 s 内有效）。

## 17. 术语表

| 词 | 意思 |
|---|---|
| 接缝 / seam | 宿主暴露的扩展点（`ctx.on('tools/pre-execute')` 等） |
| 面 / surface | 五个防护面：输入/工具调用/工具结果/模型输出/审批桥 |
| preset | 三档预设 `observe` / `balanced` / `hardened`，展开成每面默认值 |
| volatile 字段 | 标了 `.volatile()` 的配置项，宿主可热更新（不重挂载插件） |
| 账本 / ledger | `ledger.ndjson`，每条记录带 `sha256` 与 `prev_sha256` 成链 |
| 姿态 / posture | 加载期/按需的 10 项自检；`failOn` 里的码可拒载 |
| 巡检 / patrol | 运行期 5 项检查（拒绝率、健康探针、配置漂移、账本对账、通知） |
| 判决 / verdict | judge 返回 `allow` / `block`；失败有 `unavailable`/`timeout`/`bad_json`/`empty`/`error` |
| 失败矩阵 | judge 失败 × 预设 → 拒绝还是放行（hardened 拒，balanced/observe 放行） |
| 草稿 / draft | 面板里未保存的表单；也指 AI 起草出来的候选规则（两者不同，别混） |
| 公开仓 / `dsh` | 插件的公开镜像仓，树 = 插件包根，独立 tag `v1.x` |

### 1.1 2026-11-23 下午：P0「姿态沙箱假 OK」已修（1.16.2）

**症状（本机实测）**：会话的文件策略是 `danger-full-access`（会话策略明示，且工作区外写入确实成功），`safeharness_posture` 第 1 项却报 `OK / "sandbox mode is workspace-write"`。`hardened.posture.failOn` 含 `sandbox_danger_full_access`，只认 FAIL ⇒ **这道加载门禁从来没可能拦住任何部署**。

**根因**：DSH 的沙箱模式**按会话**解析。`sandboxPolicy.resolve({ session })` 折该会话的 `sandbox/mode` 事件；**不带 session** 的 `resolve()` 只返回部署默认值。1.16.1 及以前问的是后者（还多传了 `{}`）。

**证据（都是可复跑的脚本）**：

| 脚本 | 证明什么 |
|---|---|
| `scripts/probe-sandbox-semantics.mjs` | 驱动**宿主真实的** `SandboxPolicyService`：不带 session 恒为默认值；带 session 时，被切到 `danger-full-access` 的会话返回 `danger-full-access` |
| `scripts/read-session-frames.mjs <session-dir>` | 会话日志是**多帧 zstd**，单次解压只能看到头；本脚本逐帧读出全部事件 |
| `scripts/replay-sandbox-posture.mjs <session-dir>` | 把真实会话日志重放进取库后的代码：本会话 `sandbox/mode = danger-full-access`，旧口径 `workspace-write`，新口径 `WARN — sandbox mode is danger-full-access …` |

**修法**：新增 `src/hooks/sandbox.ts`；`PostureEnv.sandboxMode` → `PostureEnv.sandbox`（部署默认 ∪ 所有已观察会话的**最宽**值 + 逐模式计数 + 读不到的值/会话数）；采集点 = `agent/pre-step` / `tools/pre-execute` / `approval/request` + 会话 `sandbox/mode` 事件；每会话只解析一次。**读不到的会话按 WARN/FAIL 计，不再算 OK**。

**收口时补的三条（同日 15:05，同一版内，未另发版）**：

1. **只有部署默认值时是 `SKIP`，不是 `OK`**。加载门禁**故意**在任何接缝接线之前跑（拒绝加载 = 我们的东西一个都没活着），所以那一刻 `observedSessions === 0`、只有默认值可读。原实现会在那里报 `OK` —— 假 OK 换个位置复现。现在只有默认值 → `SKIP`；hardened 这道门禁实际拦的是"**默认值本身危险**"，会话切宽只能在会话出现后由 `safeharness_posture` / 巡检报 `FAIL`（插件已在跑）。这是接缝顺序的物理限制，写进 MANUAL §5.2 与 §11 第 26 条。
2. **LRU 淘汰不还债**：`MAX_SESSIONS = 256`。被测会话跑过一次 `danger-full-access` 后被挤出，`sandboxSummary()` 会忘记它、姿态重新变干净。现在淘汰时把**最宽模式**与"探测过但读不到"的计数留在 `sandboxEvictedPeak` / `sandboxEvictedUnknown` 里，作为下限继续计入。
3. **读不到的部署默认值也算未知**：已观察会话都读得到、但会话无关的 `resolve()` 读不到时，新增会话会落到一个没人读过的默认值上，计入 `unknownSessions`。

**测试口径**因此从 953 变成 **958**（`tests/sandbox-observe.test.ts` 13→17 条，`tests/posture.test.ts` 25→26 条）；`tests/failure-matrix.test.ts` 的 `healthyEnv()` 此前还在写已删的 `sandboxMode` 字段（TS 只检查 `src/`，所以没拦住），同批修正。

推送经常 `Recv failure: Connection was reset` / `Failed to connect … 443`，**重试循环**即可：

```powershell
$env:GIT_TERMINAL_PROMPT='0'
for($i=1;$i -le 10;$i++){ git -c http.version=HTTP/1.1 push github HEAD:main 2>&1 | Out-Null; if($LASTEXITCODE -eq 0){ "PUSH OK $i"; break }; Start-Sleep 4 }
git rev-list --count github/main..HEAD   # 必须是 0（别用退出码判断）
```

**注意**：`$LASTEXITCODE` 判成败；循环跑完但全失败时脚本退出码仍是 0，**要看 ahead 计数**。
2026-11-23 实测：一次 8 次重试才成功，一次 `ls-remote` 重试 6 次才通。

## 6. 本轮做了什么（1.15.2 → 1.16.1，逐版）

### 6.1 1.16.0（2026-11-20）工具参数形状规则

**目标**：对齐内核 `constrain.py` 的 argument-schema 那一半（`policies/_schema.py`
`validate_arguments`）。这是《plan-2026-11-18》里 1.16.0 那一项，也是最后的**能力**缺口。

**配置面**：新增 `tools.argSchemas`（非 volatile，走 profile patch；面板 1.16.x **只读**）：

```yaml
tools:
  argSchemas:
    - name: workspace_write_only      # 账本里的 rule_id（省略则 arg_schema_<序号>）
      tool: 'fs_write*'               # 工具名 glob，与 denyTools 同语法
      args:
        path:
          pathPrefix: '/workspace'
          maxBytes: 1024
        mode:
          enum: ['append', 'overwrite']
```

**六种原语**（全部线性时间可判定，**不是 JSON Schema**）：

| 关键字 | 语义 |
|---|---|
| `pattern` | 整值必须匹配；走**规则 loader 同一道 ReDoS 门**（`checkRegex`，已导出复用） |
| `enum` | 值必须在列表里 |
| `minBytes` / `maxBytes` | UTF-8 **字节**上下界（不是 UTF-16 单元） |
| `pathPrefix` | 路径必须在该前缀下；**任何 `..` 段直接拒**；`/workspace-evil/x` 不算 `/workspace` 下；`\` 归一成 `/` |
| `urlScheme` | URL scheme 必须在列表（小写、不带 `:`）；无 scheme 直接拒 |
| `commandAllowlist` | 第一个 token 必须在列表；**先查 shell 元字符**（`; & | \` $ < > ( ) { }` 与换行）；拒前置赋值（`LD_PRELOAD=x git …`） |

**判定**：`tools/pre-execute` 第 **(4b)** 步，排在 `denyTools`/`denyTags`/参数字节上限/SQL
**之后**、轨迹链**之前**。`denyTools` 与 SQL 先赢；同一工具**第一条**匹配的 schema 生效；
只约束**实际传了**的参数（必填是工具自己参数 schema 的事）；文本约束落到非字符串值上 →
fail-closed。

**记账**：`ReasonCode.ToolArgument = 'unauthorized_tool_argument'`，category `tool_argument`，
`rule_ids = [schema 名]`。**参数原文永不入账**（账本只有 `args_sha256` / `args_chars`）。

**失败方向**：某条 schema 编不过 → **只丢这一条** + 姿态第 11 项 `arg_schema_invalid`（WARN，
默认**不进** `failOn`）。一个可选 schema 的笔误不该让插件起不来，但绝不静默。
关键字集合**闭合**：`regex:` 写成 `pattern:` 会被报错，而不是编成一个什么都不查的 schema。

**文件**：新增 `src/engine/argschema.ts`（526 行）；改 `config.ts`（+39）、`engine/tool.ts`
（+40，接入判定）、`engine/types.ts`（+2，ReasonCode）、`engine/rules.ts`（+12，导出
`checkRegex`）、`posture/checks.ts`（+21，第 11 项）。

### 6.2 1.16.1（2026-11-20）`credential_assignment` 不再把自己人当密钥

**症状**（真实踩到）：维护插件时编辑 `src/config.ts`（里面有 `const secret = readField(entry.secret, …)`
这类字段声明）会触发结果面 block；`results.mode: enforce` + `blockOn: ['credential_leak']` 下
**文件其实已经改好**，模型拿到的却是拒绝话术，同批 `read` / `grep` 也返回拒绝文本。

**根因**：`credential_assignment` 的值分支把「名字 = 八字符以上一串」一律当密钥，于是三种
**自己人**的形状命中：① 源码里的调用赋值；② 测试夹具里的模板占位（`${…}` 拼 key）；
③ 插件自己的脱敏占位符（`[REDACTED…]`）。

**修法**（三处收窄，**零放宽**）：
1. 非引号值加尾部否定前瞻——值后紧跟 `(` ＝被调用的标识符，不是字面量；
2. 引号值排除**以模板占位符开头**的值；
3. 引号值排除**以本插件脱敏占位符开头**的值。

**没放宽的**：引号字面量、裸字面量、以及「只是中间含 `{`」的真令牌都仍然命中。
`tests/credential-precision.test.ts` 8 条两侧都钉（假 key 全部运行时拼出来）。

**同批写清的边界（文档）**：

- MANUAL §11 第 25 条：结果面 `block` 跑在**工具执行之后**，对写工具是**事后告警**，
  且**模型看到"被拦截"会重试 → 二次执行**（`write`/追加/命令类不是幂等的）。
- MANUAL §4.10 新增「想达到什么效果 → 配哪个字段」对照表：
  `denyTools`/`askTools`/`argSchemas` 是**事前真拦**；`results.blockOn` 只管「内容不进模型」；
  `output.mode: enforce-buffer` 管「用户看不到」。
- MANUAL §12 边界补一句：**看接缝在宿主管线里的位置，不要看 `mode` 的名字**。

**新增两个只读诊断脚本**（`scripts/`，不进包、不影响运行时）：

| 脚本 | 作用 |
|---|---|
| `scripts/mask-lines.mjs <file> <from> <to>` | 打印行区间，**把每个字符串字面量替换成 `<长度>`**。用于阅读含凭据形状的源码 |
| `scripts/credential-shapes.mjs <file...>` | 从 `src/engine/tool.ts` **抽取正在生效的那条正则**，逐文件匹配，只输出 行号/键尾/分隔符/引号/值长度/字符类，**从不输出值本身** |

它们存在的理由很实际：一条把源码当密钥的规则会让人**看不到要改的代码**，而看不到就是
下一次误报的起点。

### 9.2 明确不移植（服务端/宿主形态）

工具网关与 HMAC/Ed25519 回执、重放库、PG 审计 sink、多租户、`admin_ui/` + 受控变更
（重认证/幂等键）、`evolution/content_gate.py`、`communication/`（智能体间消息）、
审批 TTL/approver（宿主对话框托管）、OS 沙箱实现（宿主 `sandboxPolicy`）、
运维面（health_detail / chat_bridge / coordination_cli）。

**判断标准**：内核里「需要跨进程 / 数据库 / 管理面才能成立」的能力，一律不搬；
写清楚「为什么不成立」比假装做了更有价值（MANUAL §8 有完整表）。

### 9.3 为什么必须重写而不是调 Python

DSH 的 agent loop 在 Node 进程内，安全钩子必须在同一次调用栈同步/异步返回 allow/deny。
Python 侧是独立进程/服务，无法在 `tools/pre-execute` 返回前完成判定；即使能，也引入
IPC 延迟，且覆盖不了同步 `ctx.tools.guard()`。所以把需要的判定**逐个移植为纯函数**，
保持与 Python 引擎相同的规则语义，同时保持运行时零依赖。
（可选 sidecar `engine.kind: sidecar` 是另一条路：让 Python 参与输入面判定，但不是默认。）

### 9.4 Python ↔ TS 的一致性证据

- **黄金一致性**：20 条 inform 规则与 SQL 判定在内部语料上 **30/30 一致**
  （`tests/golden.test.ts` + `tests/corpus.ts` + `tests/fixtures/golden.json`，
  **内部资产，不随公开仓分发**；公开树里这 3 个用例自动跳过）。
- **sidecar 一致性**：内置引擎与真实 Python 引擎逐条比对（`tests/sidecar-parity.test.ts`，
  同样需要内部语料与本机 Python）。
- 公开树口径：**56 文件 / 892 passed + 12 skipped**（跳过的是需要内部资产的用例）。

## 13. 坑与铁律（每条都踩过）

1. **PowerShell 5.1 会把 UTF-8 文件读成 GBK**：`Get-Content -Raw` / `Set-Content`
   处理中文源码会造成**整文件乱码**。改文件优先用编辑器工具（read/edit/write）；必须用脚本时走
   `[System.IO.File]::ReadAllText / WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`，
   并且**用绝对路径**（.NET 的当前目录是进程 CWD，不是 PowerShell 的 `cd`）。
2. **文件可能被工具整篇重写成 CRLF**：本仓 `.gitattributes` 是 `* text=auto eol=lf`。
   提交前统一：
   ```powershell
   $t=[System.IO.File]::ReadAllText($p); if($t.Contains("`r`n")){ $t=$t -replace "`r`n","`n"; [System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false))) }
   ```
   复核：`git diff --ignore-cr-at-eol --stat`（只应剩真实改动）。
3. **PowerShell 没有 heredoc**，也没有 `??`：`git commit -F - <<'MSG'` 会报语法错，
   `$x ?? 0` 会报「表达式或语句中缺少 `)`」。把消息写成 UTF-8 文件再 `git commit -F 文件`。
4. **`Set-Content -Encoding UTF8` 会加 BOM**，`git log --format='%s'` 会把 BOM 带进 commit
   subject（`EF BB BF`）。用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`，
   提交后核：`$b=[System.Text.Encoding]::UTF8.GetBytes((git log -1 --format='%s')); $b[0] -eq 0xEF` 应为 False。
5. **`Invoke-WebRequest` 在本会话非交互模式下会报「朗读和提示功能不可用」**（走 IE 引擎）
   → 用 `curl.exe`；`[System.Net.Http.HttpClient]` 在本机 PowerShell 里没有该类型。
6. **esbuild 输出 ASCII 转义**：`lib/client.js` 里的中文是 `\uXXXX`，`Select-String` 查
   中文会假阴性；查 ASCII 标记（函数名/数值）或 `node -e` 读文件。
7. **pnpm 祖先 `packageManager` 陷阱**：`C:\Users\xiaojue\package.json` 声明 `yarn`，
   在没有 `package.json` 的目录里跑 DSH 自带 pnpm 会直接报错。装插件时把 cwd 切到 profile 目录。
8. **插件自己的守卫会拦你的测试数据**：工具结果/输出里出现凭据形状的字符串会被本插件拦下。
   测试里把假 key **运行时拼出来**（`['yXcX','Abc123','XpJ'].join('')`），不要写字面量。
   **1.16.1 起源码声明/模板占位/自身占位不再误报**，但真字面量仍会被拦。
9. **judge 有递归防护**：请求带 `[safeharness-judge]` 标记 + 内部 Symbol，`llm/stream`
   看到就跳过；judge 永远不会评审自己。判 `block` 在 `warn` 下只记账，`enforce-buffer` 才整条替换。
10. **账本轮转 64 MB**：`ledger.ndjson` 已 11.9 MB，别整份读进内存分析；用
    `Select-Object -Last N` 或按 `seq` 定位。
11. **改 Profile JSON 要看两处**：`cordis.patch.yml` 里可能同时有 `safeharness` 的
    `config` 块与 `append-safeharness-block.ps1` 维护的不变量段；手写 `config` 是
    **整段替换**而不是深合并，只写 `judge` 会让 `providers` 消失（桌面主对话模型随之不可用）。
12. **主项目 pytest 的 TMP 坑**：`F:\AgentSecurity\Upear` 下跑 pytest 会因
    `pytest-current` 权限失败，先 `$env:TMP='F:\tmp\pytest-tmp'`。
13. **perf 测试偶发挂**（已知，非回归）：`tests/perf.test.ts` 的
    `tool-result scan … <64 KB` 与 `… 256 KB` 两条 p99 门在**满载全量跑**时会挂
    （实测 61KB 单独跑 3.0–4.3 ms，全量跑 4.5–7.9 ms；预算 5 ms）。**单独重跑通过即正常**，
    机器空闲时 4 次全量全绿。已确认与 1.16.1 无关（Stash 掉改动后基线树上也出现过）。
    **写新的 perf 用例时规模要克制**：1.16.0 曾写过 400×5 次 × 64 KiB 的用例（分配约 128 MB），
    把 GC 停顿推给**上面几行**的预算用例，导致全量 4 次里 3 次失败。现在那条是 16 KiB × 100 次
    并放在文件最后。
    **1.16.2 起这件事在 `vitest.config.ts` 里结构化解决了**：拆成 `unit` / `perf` 两个 project，
    perf 只跑 `tests/perf.test.ts` 且 `fileParallelism: false`、`maxWorkers: 1`（测量的是代码路径，
    不是同时跑的几个 worker）。预算本身**没有放宽**——放宽就不是回归看门狗了。`npx vitest run`
    仍然两个都跑；只要单元用例用 `--project unit`。同批还修了两处「预算测的是最大值」的坑：
    `percentile(samples, 0.99)` 在 100 个样本上取到 index 99 = 最大值；`credential_assignment`
    的两条**必要**前置（含 key-ish 词、含 `=`/`:`）把它从 61 KB 文本的主成本项上摘了下来。
14. **`git worktree add` 在 PowerShell 里会走 stderr**：命令成功但 `$LASTEXITCODE` 可能是 1，
    看输出里的 `HEAD is now at …` 而不是退出码。
15. **`tsconfig.json` 只 include `src/**/*.ts`**：测试树**从来没有**被类型检查过。1.16.2 收口时
    才发现 `tests/failure-matrix.test.ts` 的 `healthyEnv()` 还在写 1.16.2 已删掉的
    `PostureEnv.sandboxMode` ——`{...PostureEnv}` 里多一个字段不会报错，于是那条用例里的沙箱
    一直是 `SKIP`，而没人知道。改 `PostureEnv`/`PostureConfig` 这类被测试大量构造的类型时，
    **先临时建一个同时 include `tests/**` 的 tsconfig 跑一次**（整树约 26 个**既有**错误，
    全是历史包袱；只看有没有**新增**的），或者至少 `grep` 一遍 `tests/` 里的字段名。

### 14.2 端点（**全部 POST-only**，`GET` 返回 405 + `Allow: POST`）

| 端点 | body | 说明 |
|---|---|---|
| `/safeharness/status` | `{}` | 概览载荷（会话/规则/计数器/账本健康/事件窗口） |

| `/safeharness/write-rule` | `{op:'write'|'history'|'rollback', …}` | 草稿落地 / 快照列表 / 回滚（1.14.0） |
| `/safeharness/settings` | `{op:'read'|'save'|'probe'|'add-provider'|'delete-provider', …}` | 面板读写；`save` 带 `expectedRevision` |
| `/safeharness/export` | `{limit?}` | 账本片段（≤500 条，已是脱敏记录） |

**栅栏**：只接受 loopback Host（`net.isIP()` **严格 IPv4**，不用 `127.` 前缀——防 DNS
rebinding）+ 同源 Origin（带跨站标记直接拒），body ≤ **16 KiB**，单飞/冷却，写端点带
revision CAS。响应是固定投影：只有代码/名称/哈希/计数/短 id/路径，**不含** prompt、
参数原文、模型输出、webhook 或凭据。

curl 没有 Origin 头，因此能调——这是设计（本地诊断），不是漏洞；但它确实意味着
**本机任何进程**都能读面板数据，别在多用户机器上这么用。

### 14.3 设置页保存条语义（1.15.2 之后，改之前先读）

```
dirty  = buildPatch(value, form).patch !== undefined || .invalid !== null
按钮禁用 = !dirty || invalid !== null || readOnly || saving
readOnly = !value.judge.configurable
```

- `buildPatch` 是纯函数（已导出，供测试）：逐字段 diff，只把动过的字段放进 patch，
  并回传 `expectedRevision`（宿主 patch 修订号，**进程重启后归 0**）。
- 非法值也是「有未保存的修改」，理由显示在**保存条内**；按钮 `title` 说明原因。
- 草稿写 `sessionStorage`，键 `safeharness.panel.settings-draft`，带 `baselineOf(value)`；
  基线**只含可编辑字段**，探针状态翻转不会清草稿。
- 保存成功写 `safeharness.panel.settings-saved`，宿主重载导致面板重挂时用它继续显示
  「已保存」（15 s 内有效）。

## 18. 术语表

| 词 | 意思 |
|---|---|
| 接缝 / seam | 宿主暴露的扩展点（`ctx.on('tools/pre-execute')` 等） |
| 面 / surface | 五个防护面：输入/工具调用/工具结果/模型输出/审批桥 |
| preset | 三档预设 `observe` / `balanced` / `hardened`，展开成每面默认值 |

| 姿态 / posture | 加载期/按需的 11 项自检；`failOn` 里的码可拒载 |
| 巡检 / patrol | 运行期 5 项检查（拒绝率、健康探针、配置漂移、账本对账、通知） |

| 失败矩阵 | judge 失败 × 预设 → 拒绝还是放行（hardened 拒，balanced/observe 放行） |
| 草稿 / draft | 面板里未保存的表单；也指 AI 起草出来的候选规则（两者不同，别混） |
| 公开仓 / `dsh` | 插件的公开镜像仓，树 = 插件包根，独立 tag `v1.x` |
| 内部资产 | **永远不进公开仓**的文件：攻击语料、golden/benign fixture、生成器、读它们的测试 |
